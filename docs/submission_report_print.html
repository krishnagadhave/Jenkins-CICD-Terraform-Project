2. Cloud-Native Microservice Architecture

To demonstrate authentic CI/CD integration, a dedicated cloud-native microservice was authored in Node.js with zero external runtime dependencies. This design guarantees ultra-fast initialization, eliminates upstream supply-chain vulnerabilities during builds, and delivers deterministic runtime behavior.

Key Endpoints & Observability Capabilities:

  • GET /api/health: Liveness probe indicating server health (returns 200 OK and uptime).
  • GET /api/ready: Readiness probe checking dependency connectivity (database and cache).
  • GET /api/info: Metadata endpoint returning student author details, PRN (202301040250), CI/CD engine, and Terraform topology.
  • GET /api/metrics: Real-time telemetry reporting memory usage (RSS, heap), CPU cores, and request counters.
  • GET /api/simulate-unhealthy: Chaos engineering endpoint to simulate failure for testing self-healing and monitoring.
  • GET /: Interactive glassmorphism Web Dashboard showing live telemetry and pipeline stepper.

3. Jenkins CI/CD Pipeline Implementation

The automated software delivery pipeline is defined in a version-controlled Jenkinsfile using Jenkins Declarative Pipeline syntax. The pipeline enforces a 7-stage quality gate that guarantees code reliability and infrastructure validity prior to deployment.

Stage # Stage Identifier Primary Objectives & Execution Commands
1 Checkout SCM Clones Git repository, verifies HEAD commit, extracts commit hash, branch name, and author.
2 Environment Check Inspects agent environment; checks node -v, npm -v, and terraform -version.
3 Code Quality & Lint Executes AST static analysis (npm run lint); checks syntax, bans eval(), checks secrets.
4 Automated Tests Executes 12 unit/integration tests (npm test); outputs JUnit XML to reports/junit.xml.
5 Build & Package Runs npm run build; copies source to dist/, generates build-manifest.json, builds .tar.gz.
6 Terraform Validation Shifts infrastructure testing left: runs terraform fmt -check and terraform validate.
7 Automated Deploy Deploys release bundle and runs automated smoke tests against live health and readiness probes.
Post Post-Build Actions Archives JUnit test report (junit) and fingerprints release artifacts (archiveArtifacts).

5. Infrastructure as Code (IaC) with HashiCorp Terraform

To eliminate configuration drift and manual provisioning errors, the entire cloud infrastructure on Amazon Web Services (AWS) is managed through declarative Terraform HCL files structured across modular components.

Manifest File Architectural Function & Declared Resources
versions.tf Declares required Terraform version (>= 1.5.0) and AWS provider (~> 5.0).
providers.tf Configures AWS provider with default project tags, student name, and PRN (202301040250).
variables.tf Declares strongly-typed variables (region, CIDR blocks, environment, instance type) with validation.
vpc.tf Provisions Custom VPC (10.0.0.0/16), Internet Gateway, Public Subnet (10.0.1.0/24), Route Tables.
security_groups.tf Configures firewall ingress rules for Port 80 (HTTP), Port 3000 (App), Port 22 (SSH), and full egress.
compute.tf Defines EC2 instance (t3.micro), encrypted 20GB GP3 volume, and cloud-init bootstrap script.
outputs.tf Exposes public IP, public DNS, application URL, and health probe endpoint.

7. Appendix: Core Declarative Manifests

Declarative Jenkinsfile (Excerpt)

pipeline {
    agent any
    options {
        buildDiscarder(logRotator(numToKeepStr: '10'))
        timestamps()
    }
    environment {
        APP_NAME       = 'cloud-native-cicd-app'
        APP_VERSION    = '1.2.0'
        PROJECT_AUTHOR = 'Krishna Gadhave'
        STUDENT_PRN    = '202301040250'
    }
    stages {
        stage('Checkout SCM') { steps { checkout scm } }
        stage('Environment Check') { steps { sh 'node -v; npm -v; terraform -version' } }
        stage('Code Quality & Lint') { steps { sh 'npm run lint' } }
        stage('Automated Tests') { steps { sh 'npm test' } }
        stage('Build & Package') { steps { sh 'npm run build' } }
        stage('Terraform Validation') {
            steps {
                sh 'terraform -chdir=terraform fmt -check'
                sh 'terraform -chdir=terraform validate'
            }
        }
        stage('Automated Deploy') { steps { sh 'node scripts/deploy-verify.js' } }
    }
    post {
        always {
            junit allowEmptyResults: true, testResults: 'reports/**/*.xml'
            archiveArtifacts allowEmptyArchive: true, artifacts: 'dist/**/*'
        }
    }
}

Terraform Compute & VPC Manifest (Excerpt)

resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  enable_dns_support   = true
  tags = { Name = "${var.project_name}-${var.environment}-vpc" }
}

resource "aws_instance" "app_server" {
  ami                         = var.ami_id != "" ? var.ami_id : data.aws_ami.ubuntu[0].id
  instance_type               = var.instance_type
  subnet_id                   = aws_subnet.public.id
  vpc_security_group_ids      = [aws_security_group.app_sg.id]
  associate_public_ip_address = true

  root_block_device {
    volume_size = 20
    volume_type = "gp3"
    encrypted   = true
  }

  user_data = <<-EOF
              #!/bin/bash
              apt-get update -y && apt-get install -y nodejs
              systemctl start cloud-native-app.service
              EOF
}
